# knowdrug 知药-代表版

这是与医生端独立的 HTML / CSS / JavaScript 交互演示项目。医生端项目位于同级 `medlink`，本项目不修改医生端文件。

启动：在本目录执行 `python3 -m http.server 8081 --directory dist`，打开 `http://localhost:8081`。

功能：

- 首页：数字人概览、近7/30天服务指标、高频提问主题、待跟进医生和功能统计。
- 数字人：上传照片、编辑名称和介绍、画面滤镜、普通话语音预览、保存草稿与本地发布版本。
- 医生洞察：医生/科室/医院搜索、主题筛选、医生提问总结、典型问题、使用数据、跟进状态与笔记。
- 统计：周期切换、趋势指标切换、柱状图点击、功能下钻、医生使用排行及 CSV 导出。

数据边界：

- `dist/data.js` 为确定性合成样例，所有人数、提问量、功能次数与图表由同一事件集合计算。
- 代表端未读取医生端的实际使用记录；两端尚无后台数据同步。
- 照片在浏览器中缩放压缩并保存，不上传网络。发布仅保存当前浏览器的形象版本，不会改动医生端。
- 形象预览使用照片与浏览器普通话 TTS，不包含口型驱动或真实数字人视频生成服务；语音支持取决于浏览器。
- 草稿、形象版本、笔记与跟进状态使用独立的 `knowdrug-representative-` localStorage 命名空间。
- 示例数据不包含患者病例正文。

原型使用与医生端一致的系统中文字体、480px移动布局、底部导航和底部弹层。主色为浅绿色，沿用现有生成的虚拟代表肖像。

当前演示药品统一为日达仙。相关条目为资料阅读框架与交互样例，不增加具体适应症或用药剂量信息。

## 会议功能

- 医生端：首页与底部导航的“会议”入口，按全部邀请 / 待处理 / 已报名和线上 / 线下筛选。打开详情才记录首次查看；可回复不参加，或确认参加后填写姓名、医院、科室、手机号并授权报名。报名成功后显示编号、会务安排；截止前可取消、重新报名。
- 代表端：“会议”查看后台会议、会议时间、地点、议程与报名截止日期；选择医生批量发送，重复发送不会覆盖已有阅读和报名状态。详情独立显示已邀请、已查看、愿参加、已报名及每位医生的首次阅读、回复和报名时间，支持状态筛选。
- 会议目录为浏览器首次打开时生成的合成样例，未接真实后台下发接口。线上会议安排是产品交互占位，未接入真实会议室、短信通知、签到或实际出席追踪；“愿参加”和“已报名”不等于实际出席。
- 两端联动：使用同一个浏览器配置文件打开医生端和代表端。会议状态只保存在医生端 origin 的 `knowdrug-meetings-v1` localStorage，通过限定 origin 的消息桥供代表端读取和发送邀请；每5秒及页面恢复时刷新。无服务器或跨设备同步。默认医生为张医生（d1）；已有同名合成医生资料会映射到对应医生。
- 所有会议邀请仅改变本浏览器的数据，不会向真实医生发送消息。报名联系方式只保存在本浏览器，查看报名信息时遮挡手机号中间四位。
- 本地联调需同时启动医生端 `http://localhost:8080` 和代表端 `http://localhost:8081`；保持两个项目的 dist 完整。生产桥接地址在 `dist/meeting-store.js` 中配置，如更换部署域名，需同时更新双方允许的 origin。浏览器需允许站点存储；连接失败会显示重试而非产生一份独立数据。

状态检查：在项目目录执行 `node tests/meeting-store.test.cjs`，验证发送、幂等、阅读、意向、报名校验、取消、再次报名、截止限制与持久化。
